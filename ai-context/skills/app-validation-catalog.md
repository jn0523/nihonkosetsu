## 2. 【全機種共通】テスト項目・手順

### 2.1 表示・ライト/ダーク両モード・アクセシビリティ
- [ ] **ライトモード基本確認:** ライトモード下で全画面の背景色・文字色・カード境界が正常に視認でき、レイアウト崩れがないこと
- [ ] **ダークモード基本確認:** ダークモード下で全画面の背景色・文字色・アイコンが正常に反転・表示され、暗所での可読性が確保されていること
- [ ] **テーマ切替即時反映:** OSのライト/ダーク設定切替およびアプリ内の「システム/ライト/ダーク」設定切替が、再起動なしで全画面に即時追従すること
- [ ] **コントラスト比担保 (WCAG 2.1 AA 4.5:1以上):** 黒背景に黒文字、白背景に白文字、濃色背景に薄グレー文字などの可読性破綻が一切ないこと
- [ ] **オーバーレイ整合性:** アラートダイアログ、ModalBottomSheet、ドロップダウンメニュー、ピッカーの背景サーフェス色と文字色の白飛び・黒潰れがないこと
- [ ] **Dynamic Type (文字拡大):** OSフォントサイズ最大化時、重要情報（数値・ステータス等）の見切れやボタン押下不能が発生しないこと

### 2.2 料金プラン選択・課金ライフサイクル・購読失効制御
- [ ] **プラン選択・表示確認:** 月額・年額・買い切り等の各料金プランがPaywall画面に正しく表示され、プランごとの金額・請求周期・無料体験期間が正確であること
- [ ] **プラン切替・選択動作:** 異なるプラン（月額 ⇔ 年額）をタップした際、選択状態（ハイライトやラジオボタン）が即座かつ正確に切り替わること
- [ ] **購入フロー完了:** サンドボックス環境で選択したプランの購入が正常に完了し、即座にPro機能が解放されること
- [ ] **動的プラン・価格反映:** RevenueCat等のリモート設定で価格やオファーを変更した際、アプリ本体の更新なしで即時反映されること
- [ ] **購入の復元 (Restore):** アプリ再インストール時や別端末で「購入を復元する」を実行し、過去の購読状態が復旧すること
- [ ] **【最重要・失効時検証】有料オプション遮断:** 有料プラン失効（期限切れ・解約・返金）後、Pro限定機能が即座にロックされ、Paywallへ誘導されること
- [ ] **【最重要・失効時検証】超過データ保全:** Pro時に作成した上限超過データ（例: 上限3件に対し10件作成）が削除されず、閲覧・保持・削除できること
- [ ] **【最重要・失効時検証】超過時新規追加ブロック:** 上限超過状態において新規作成・追加が確実にブロックされ、親切な再購読導線が表示されること
- [ ] **ステータス表示整合性:** 失効後にアカウント画面のProバッジ・VIP表示がFree仕様に正常に戻ること

### 2.3 基本動作 & データCRUD
- [ ] アプリアイコンタップで正常起動し、クラッシュしないこと
- [ ] スプラッシュ画面から初期画面への遷移、およびオンボーディングの初回保存
- [ ] バックグラウンド移行 ⇔ 復帰時のフリーズ・白画面化の防止
- [ ] オフライン状態でのローカルデータ作成・更新・閲覧、およびオンライン復帰時の自動同期

### 2.4 AI機能 & 耐障害性
- [ ] 空入力・空白のみ・極小入力時の適切なバリデーション表示とリクエスト抑止
- [ ] 想定上限を超える長文（5,000〜10,000文字）入力時の安全な制御
- [ ] FreeプランのAI利用回数制限カウントと、上限到達時の案内表示
- [ ] APIレートリミット（429）、クォータ枯渇、サーバーエラー時の親切な日本語案内
- [ ] AI生成中の安全なキャンセル・中断操作、およびタイムアウト時の再試行案内
- [ ] 壊れたJSONや想定外フォーマットに対するフォールバック処理

## 3. 【機種別】固有テスト項目・手順

### 3.1 iPhone (標準 / Plus / Pro / Pro Max)
- [ ] **SafeArea干渉:** ノッチ、Dynamic Island、ステータスバー、ホームインジケーター（ホームバー）とボタン・ヘッダー・フッターが重ならないこと
- [ ] **片手操作性:** 片手操作時の主要ボタン（FAB・下部タブ・アクションボタン）へのタップ容易性
- [ ] **キーボード追従:** テキスト入力時にソフトウェアキーボードが表示された際、入力中のテキストフィールドが隠れず自動スクロール追従すること

### 3.2 iPad mini (コンパクトタブレット)
- [ ] **コンパクト画面密度:** 8.3インチ級コンパクト画面特有のアスペクト比において、情報密度が過密・過疎にならず快適に操作できること
- [ ] **フォント・ボタン見切れ防止:** ツールバーやヘッダーの凝縮表示時に、アイコンやテキストが見切れたり省略（...）されすぎないこと
- [ ] **Split View最小幅:** 画面分割（Split View）で最小幅にした際、主要UIが崩れずスクロールで全要素にアクセスできること

### 3.3 iPad (標準 / Air / Pro 大画面タブレット)
- [ ] **大画面ナビゲーション:** NavigationSplitView（2カラム/3カラム）でのサイドバー開閉・コンテンツ表示の余白バランスが自然であること
- [ ] **マルチタスク (Stage Manager / Split View / Slide Over):** ウィンドウサイズ変更時にクラッシュやレイアウト破綻がなく、リサイズに即時追従すること
- [ ] **画面全方向回転:** 縦画面・横画面（全4方向）回転時にレイアウトが維持され、ダイアログの決定・閉じるボタンが画面外に見切れないこと
- [ ] **外付けデバイス操作:** ハードウェアキーボードのショートカット（Cmd+Enter等）およびトラックパッド/マウスによるポインタ・ホバー効果が正常に機能すること

### 3.4 iPhone Duo / 折りたたみ端末 (Foldable / Dual-Screen)
- [ ] **ヒンジ（折り目）回避 (Hinge Avoidance):** 中央のヒンジやベゼル境界領域に、文字やタップ対象ボタンが重ならず左右/上下に適切に配置されること
- [ ] **開閉アスペクト比変化:** 端末の開閉（折りたたみ ⇔ 展開）時に画面がクラッシュ・リロードせず、シームレスに画面比率が追従し、フォーム入力中のデータが保持されること
- [ ] **2画面分割活用:** デュアル画面展開時、左画面に一覧/メニュー、右画面に詳細/プレビューが安定して表示されること

### 3.5 Android (多様な解像度・OS仕様)
- [ ] **システム戻るキー/ジェスチャー:** 端末の「戻る」ボタンまたは画面端スワイプジェスチャーで、モーダルが正しく閉じ、意図した画面スタックへ遷移すること
- [ ] **多種アスペクト比追従:** 16:9, 19.5:9, 21:9 等の縦長画面や小型画面において、UI要素のオーバーフロー（レイアウト崩れ）が発生しないこと
- [ ] **OSフォント・表示サイズ最大化:** Android設定の「フォントサイズ」「表示サイズ」を最大にした際、重要なUIやボタンが画面外に押し出されないこと
- [ ] **権限ハンドリング:** 通知・ストレージ・カメラ等の権限要求ダイアログで「拒否」を選択した際、クラッシュせず親切な再案内を行うこと

## 2. 「ダークモード・画面表示」詳細検証マトリクス

| 検証項目 | 検証シナリオ | 期待結果・OK基準 | NG・よくある不具合例 |
| :--- | :--- | :--- | :--- |
| **即時テーマ切替** | OS設定（コントロールセンター）でライト/ダークを切り替え | アプリの再起動なしで全画面の背景・文字が即時追従する | アプリを再起動しないとテーマが変わらない、一部画面だけ白いまま |
| **テキストコントラスト** | ダークモード下で各画面の本文・補足・ラベル・数値を視認 | 背景（濃色）に対して十分な明度差（コントラスト比4.5:1以上）があり読みやすい | 薄いグレー文字（#666666）が黒背景に溶け込んで読めない |
| **入力フォーム & プレースホルダー** | テキストフィールドの非活性時、フォーカス時、文字入力時 | 入力文字、プレースホルダー文字、カーソル色が明確に見える | プレースホルダーが白飛びする、入力文字が黒色で入力中に見えない |
| **オーバーレイ & ダイアログ** | アラートダイアログ、ModalBottomSheet、ActionSheetを表示 | ダイアログの背景がダークテーマ用サーフェス色になり、境界が明確 | ダイアログ背景が真っ白のままで文字が白くなって読めない |
| **リスト・カード・仕切り線** | カードコンポーネント、ListTile、Dividerの表示 | カード境界や仕切り線が適切な濃淡で視認でき、立体感が損なわれない | 境界線が完全に見えなくなり、リスト項目同士の境界が判別不能になる |
| **アイコン・透過画像** | 黒色単色アイコン、カスタムSVG、アプリアイコンの表示 | アイコン色がテーマのオンカラー（白色・淡色）に適応される | 黒いアイコンが黒背景に溶けて消える |
| **横画面回転（Orientation）** | 横画面にしてダイアログや長いフォームを開く | スクロール可能（SingleChildScrollView等）で、OK/キャンセルボタンが押下可能 | ボタンが画面外（下部）に押し出されてスクロールできず詰む |
| **Dynamic Type (文字拡大)** | OSのアクセシビリティで文字サイズを最大に設定 | 文字が重ならず折り返され、主要機能の操作が可能 | テキストがオーバーフロー（A RenderFlex overflowed...）、ボタンがはみ出る |
| **SafeArea (ノッチ・バー干渉)** | 画面上部（Dynamic Island/ノッチ）、画面下部（ホームバー） | 上部ヘッダーや下部アクションボタンがシステムUIと重ならない | 時計やバッテリー表示とアプリの戻るボタンが重なってタップしづらい |

## 3. 「課金ライフサイクル・購読失効制御」詳細検証マトリクス

### 3-1. テスト環境準備
- **iOS:** Xcode StoreKit Configuration ファイル（`.storekit`）を作成し、`Time Rate`（時間の進み方: 例 1時間＝1秒）を設定して購読更新・失効を高速シミュレートする。
- **Android:** Google Play Console のライセンステスト（License Testing）アカウントを使用し、テスト購入（Test card, always approves / declines）およびテスト更新間隔（5分）で検証する。
- **RevenueCat:** Sandbox環境ダッシュボードでユーザーID（App User ID）を検索し、購読の手動付与・失効・更新イベントを確認する。

### 3-2. 課金失効・ダウングレード検証マトリクス
| 検証シナリオ | 手順 | 期待結果・OK基準 |
| :--- | :--- | :--- |
| **通常購入 → Pro反映** | Paywall画面から月額または年額プランを購入 | 即時に購入成功トーストが表示され、Pro専用機能が解放される |
| **購入復元 (Restore)** | アプリをアンインストール後再インストールし、「購入を復元」をタップ | RevenueCat/StoreKitから以前の有効な購読が取得され、Pro状態に戻る |
| **【最重要】有効期限切れ（失効）** | StoreKit Configurationで購読をExpireさせる、またはサンドボックスで解約後期限を迎える | **次回アプリ起動またはレジューム時に自動でFree状態へ降格する** |
| **失効後の有料オプション制御** | 有料プラン限定機能（例: 高度フィルター、CSVエクスポート、特定画面）を開く | **機能がロックされ、再購読を促すPaywall画面が表示される** |
| **失効後のデータ保全 (閲覧・削除)** | Pro状態で上限（Free上限: 3件）を超えて作成したデータ（例: 10件）を確認 | **既存の10件は削除されず、一覧表示および詳細閲覧・削除が可能** |
| **失効後の新規追加ブロック** | 上限（3件）を超過している状態で「新規作成」ボタンをタップ | **「無料プランの上限（3件）に達しています」と案内され、新規登録が阻止されてPaywallへ誘導される** |
| **失効後のデータ削減による再開** | 既存データを削除してFree上限以下（例: 2件）にする | **上限以内になったため、Free枠として新規作成が再び可能になる** |
| **オフライン時の猶予期間** | 購読失効直前に端末を機内モードにし、有効期限経過後にアプリを起動 | クラッシュせず、キャッシュされた前回の状態または安全な縮退動作をする |
| **購入失敗・キャンセル** | 購入画面で「キャンセル」またはカード決済エラーを発生させる | アプリが元の画面に戻り、Pro状態にならずエラーメッセージが適切に出る |

## 4. 「AI機能・LLM連携」詳細検証マトリクス

| 分類 | 検証シナリオ | テストデータ・操作例 | 期待結果・OK基準 |
| :--- | :--- | :--- | :--- |
| **入力バリデーション** | 空文字 / スペースのみ | `""` または `"   \n  "` を入力して送信 | 送信ボタンが非活性、または「入力してください」と即時警告 |
| **入力バリデーション** | 境界値（長文・巨大テキスト） | 5,000文字以上の長文テキストをペーストして送信 | クライアント側で上限検知（例: 最大2,000文字まで）、または適切なチャンク処理 |
| **入力バリデーション** | 特殊文字列・記号 | `<script>alert(1)</script>`、絵文字の連続、Markdown記法 | 文字列として安全にエスケープされ、UI崩れやエラーなくAIに渡る |
| **入力バリデーション** | 不正URL（URL解析機能時） | 存在しないドメイン、404ページ、画像直リンク | 「URLから情報を取得できませんでした」と分かりやすい日本語で通知 |
| **利用上限制御** | Freeプランの回数制限 | 1日3回制限のアプリで4回目のリクエストを実行 | 「本日の無料利用枠（3回）を使い切りました。明日またご利用いただくか、Proプランへアップグレードしてください」と表示 |
| **ローディング体験** | AI推論待機中 | 生成ボタン押下直後〜結果受領まで | インジケータやスケルトンが表示され、ボタン連打・多重送信が完全に抑止される |
| **キャンセル操作** | 長時間推論中の中断 | 推論中に「生成を中止」ボタンをタップ | リクエストが即座に中断（AbortController等）され、UIが待機状態に戻る |
| **APIエラー制御** | レート制限（429 Too Many Requests） | 短時間に連続リクエストを送信 | 「アクセスが集中しています。数十秒待ってから再度お試しください」と表示 |
| **APIエラー制御** | クォータ枯渇（クレジット切れ） | クォータが切れたAPIキーでリクエスト | 生のJSONエラー（quota_exceeded）を隠蔽し、「AIサービスの利用枠に問題が発生しました。サポートへお問い合わせください」等と案内 |
| **耐障害性** | 通信切断（タイムアウト） | リクエスト送信直後に機内モードにする | 30秒程度でタイムアウトし、「通信環境の良い場所で再試行してください」とリトライボタンを表示 |
| **パースエラー耐性** | 不正JSON・途中途切れ | LLMが閉じ括弧なしのJSONや挨拶テキスト混じりで返却 | JSON.parseでクラッシュせず、テキスト抽出に切り替えるか、親切な再試行導線を提供 |
| **結果の整合性** | 生成結果の保存・破棄 | 生成されたカード/リストを編集後に「保存」、または「キャンセル」 | 保存時はDBに正常永続化され、キャンセル時は変更が破棄されて前画面に戻る |

## 5. チェックリスト作成時のプラットフォーム別留意点

### 5-1. iOS (iPhone / iPad) 固有
- **Dynamic Island / ノッチ干渉:** iPhone 14 Pro以降、iPhone 15/16全機種での実機・シミュレータ確認。
- **iPad Split View / Slide Over:** 画面幅が1/3、1/2、2/3になった場合の適応的レイアウト（Master-Detail崩れがないか）。
- **Appleサインイン:** Apple IDでのログイン・アカウント削除導線の必須チェック（Apple審査ガイドライン5.1.1(v)）。
- **App Intents:** ショートカットアプリからの起動、Siri連携が機能するか。

### 5-2. Android 固有
- **戻る操作（Back Navigation）:** 画面下の物理/仮想戻るボタン、および画面端からのスワイプジェスチャーで、アプリが意図せず終了せず前の画面やモーダルが閉じること。
- **キーボード表示時のレイアウト:** ソフトウェアキーボード出現時に、入力欄が隠れず画面が押し上げられること（`resizeToAvoidBottomInset`）。
- **多種多様な画面アスペクト比:** 縦長端末（20:9等）やパンチホールカメラ位置との干渉チェック。
