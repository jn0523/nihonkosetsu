# AI開発コスト最適化・モデル割当ポリシー（恒久ルール）

目的: AIを活用したアプリ開発において、タスクの難易度に応じた適切なAIモデルの使い分けをルール化し、品質・開発速度を最大化しながら開発コスト（API利用料・トークン消費・エンジニアの待ち時間・手戻りコスト）を最小化する。

---

## 1. 基本方針

1. **恒久ルールの正本:** AIモデルの選定・コスト最適化方針は本ファイルを正本とし、各実装計画書に重複して詳細を定義せず、本ポリシーを参照すること。
2. **「大は小を兼ねる」の排除:** すべてのタスクを最高性能・高単価なフロンティア推論モデルで実行することは禁止。定型作業や小規模な修正には低コストな軽量モデルを明示的に指定・使用する。
3. **トータルコストの最適化:** 難易度が高い複雑なタスクにあえて安価なモデルを当てて手戻り・バグ修正を繰り返すことは、結果として高コスト（トークン浪費と開発遅延）を招く。難易度が高いタスクには適切な高性能推論モデルを割り当てる。
4. **WBSへの明記義務:** 開発計画書の各タスク（WBS）には、必ずタスク難易度（高・中・低の3段階）と推奨モデル（Tier）を明記すること。

---

## 2. タスク難易度（高中低）とAIモデル割当マトリクス

開発作業を以下の3段階（高中低）に分類し、適切なモデルティア（Tier 1〜3）を割り当てます。

| 難易度 | モデル分類（ティア） | 代表的なAIモデル例 | 対象タスクの特性・具体例 | コスト最適化の狙い |
| :--- | :--- | :--- | :--- | :--- |
| **高 (High)** | **Tier 1: フロンティア推論 / フラッグシップ** | Claude 3.7 Sonnet (Thinking), Claude 3.5 Sonnet, OpenAI o1, o3-mini (High), GPT-4o, Gemini 2.0 Pro / 1.5 Pro | ・アーキテクチャ・DBスキーマ設計<br>・決済・認証・セキュリティなどのコアロジック<br>・複数ファイル・レイヤーを跨ぐ大規模リファクタリング<br>・原因特定が困難な難解バグの深層デバッグ<br>・複雑なプロンプトやエージェント連携設計 | 深い論理的推論により、初回での正答率を高め、設計破綻や手戻りによるトークン浪費・開発遅延を最小化する。 |
| **中 (Medium)** | **Tier 2: バランス型・標準高性能** | Claude 3.5 Sonnet, GPT-4o, Gemini 2.0 Flash / 1.5 Flash, o3-mini (Medium/Low) | ・一般的な画面（UIコンポーネント）の実装<br>・CRUD機能・標準的なAPIエンドポイント結合<br>・確立された設計パターンに沿ったサブビュー抽出<br>・標準的な単体テスト・結合テストコードの作成<br>・技術仕様書・設計書・QAチェックリストの初稿生成 | 開発のボリュームゾーンであり、コーディング速度・精度・トークン単価のバランスが最も優れたモデルで効率的に消化する。 |
| **低 (Low)** | **Tier 3: 軽量・超高速・低コスト** | Claude 3.5 Haiku, GPT-4o mini, Gemini 2.0 Flash-Lite / 1.5 Flash-8B | ・型定義、DTO、定数、Enumの記述<br>・定型的なボイラープレートコード生成<br>・i18n多言語リソース（辞書ファイル）の追加・翻訳<br>・CSS / スタイリング / レイアウトの微調整<br>・Markdownドキュメントの体裁整形・誤字修正<br>・Gitコミットメッセージ・PR概要の作成<br>・Linter / Formatter エラーの単純な一括修正 | 極めて安価かつ低レイテンシなモデルを活用し、定型作業での無駄なAPI費用消費を徹底的に削減する。 |

## 3. 開発計画書（WBS）への記載規律

開発計画書（`development_plan.md` 等）のフェーズ別タスクリスト（WBS）を作成する際は、各チェックボックス項目に以下の構文で難易度と推奨モデルを明記してください。

### 構文ルール
`- [ ] [難易度: 高/中/低 | 推奨モデル: モデルティア（具体モデル例）] タスク内容`

### 記載例
```markdown
### Phase 2: メイン機能 (MVPコア) の高速実装
- [ ] [高 | Tier 1 (Claude 3.7 Sonnet / o3-mini)] SwiftDataスキーマ定義とRevenueCat課金ステートマシンの同期ロジック設計・実装
- [ ] [中 | Tier 2 (Claude 3.5 Sonnet / Gemini Flash)] 記録一覧画面（MVファースト、サブビュー抽出）の実装
- [ ] [中 | Tier 2 (Claude 3.5 Sonnet / Gemini Flash)] レビュー促進ダイアログおよびアプリ内FB導線のUI/トリガー実装
- [ ] [低 | Tier 3 (Claude 3.5 Haiku / GPT-4o mini)] カラーパレット定数定義およびi18n多言語ローカライズ用文字列ファイルの作成
- [ ] [低 | Tier 3 (Claude 3.5 Haiku / GPT-4o mini)] コードフォーマッター適用およびリンター警告の解消
```

## 4. エディタ・ツール別モデル切替運用ガイド

AIエディタ（Antigravity, Cursor, Claude Code, Codex等）を利用する際の実践運用指針：

1. **計画策定・設計フェーズ:**
   - 計画書作成、要件定義、アーキテクチャ設計は **Tier 1 (High)** モデルを使用。
2. **実装スプリントフェーズ:**
   - 通常の実装タスクは **Tier 2 (Medium)** をデフォルトとする。
   - 難関ロジックや根本デバッグ時のみ **Tier 1 (High)** へスイッチ。
   - ボイラープレート、定数、翻訳、体裁修正などは **Tier 3 (Low)** へ切り替えて実行する。
3. **ドキュメント作成・検証フェーズ:**
   - 仕様書・テスト計画の全体構成作成は **Tier 2 (Medium)**、定型的なチェック項目展開や誤字脱字修正は **Tier 3 (Low)** を併用する。
